# 05 质检

## 1. 闷点排查（成片前必做）
**标准**：任何连续 2 秒画面基本没有变化，都要改。

```bash
python tools/dull_scan.py 成片.mp4 3.0
```
- 成片按 10fps 解码成 108×192 灰度图，去掉字幕带（1520–1740px）、右上角标、底部进度条；
- 对每个起点 t，算 [t, t+2s] 内每一帧相对 t 的平均灰度差，取最大值；最大值 < 阈值 = 闷段；
- 阈值 3.0 是第28期定的经验值（0–255）：浅色纸底上只有小元素动、大面积空白时会被抓出来。

**第28期第一次扫出 7 段，怎么改的：**

| 闷段 | 原因 | 改法 |
|---|---|---|
| 16.9–19.1 | 对话框静止，只有打字 | 整块对话框慢推 1→1.09 + 上移 |
| 41.8–43.9 | 网页原件盖章后不动 | 推镜 1.85→2.15 + 竖向漂移 |
| 44.0–46.0 | 纸底只有一根线一个点 | 相机拉远幅度加大、点上加脉冲圈、4 个限制事件签依次滑入 |
| 51.4–58.5 | 海报小，元素少 | 相机沿时间轴从 4 月一路平移到 7 月底 |
| 87.8–95.0 | 结尾全景静止 | 相机持续推近 + 右移，问号跳动 |

改完**只补渲这几段**（`patch.sh`），复扫到 `DULL_SEGS 0`。

## 2. 字幕对时
- 生成阶段：`gen_timeline.py` 逐字对齐覆盖率 < 85% 直接报错（防字幕错位）。
- 成片阶段：`python tools/final_qc.py 成片.mp4`，BAD 的逐条判断：
  - 识别误差（DeepSeek→DeepSake、0.2 秒短屏只识别到一个字、数字换算串字）→ 记录即可；
  - 真错位（屏上的字和这段时间念的话对不上）→ 查 `SC` 切屏或 `NUMS`。

## 3. 帧数
- 成片必须 30fps、帧数 = round(总时长 × 30)，音画等长：
```bash
ffprobe -v error -count_packets -show_entries stream=codec_type,nb_read_packets,r_frame_rate,duration -of csv=p=0 成片.mp4
```
- `patch.sh` 拼完会自动核对，不对就退出（第28期踩过：不加 `-r 30` 时 concat 输出成 25fps，少了 480 帧）。

## 4. 抽帧总览（肉眼）
每 3–4 秒抽一帧拼成总览，重点看：
- 新闻片里的**台标、记者字卡、滚动条**（第28期 OpenAI 镜头抽到了 CBS 的"Reporter: …"字卡，换成了总部门牌）；
- 无关人脸、vlog 自拍；
- 文字被裁、标签挡字、印章盖住标题；
- 拼接口前后有没有跳（补丁范围要盖住淡入淡出）。

## 5. 耳听清单（交给用户）
识别结果和文案不一致的词都列出来请用户听：型号（Qwen3.8-Max）、芯片（H200 读"H 二百"还是"H 两百"）、多音字。只重配那一句（`tts.py 16`），再补那一段画面。
